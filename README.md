# Wealth Tracker 2.4

個人資產與交易策略 PWA。這個版本由原本的單檔 App 改為可維護的模組，沿用原 Firebase 專案、Google 登入與管理員設定。

## 先看介面

直接以 Chrome、Edge 或 Safari 開啟 `device-preview.html`，可切換「電腦版／手機版」。`preview.html` 是不含尺寸切換框的同一份預覽。開啟預覽，不需登入、不需安裝套件。裡面的帳號、行情、持倉、朋友與策略全部是虛構示範；操作不會寫入 Firebase，重新開啟即重置。

正式入口 `index.html` 需由 HTTP／HTTPS 伺服器提供，不能用雙擊本機檔案的方式登入。正式版也可使用登入頁的「先看看新版介面」。

## 改善內容

- 恢復原版黑綠底色、米白文字與金色重點；首頁保留總資產、損益、趨勢與目標，配置與報酬試算改為可展開細節。
- 電腦側欄與寬版配置，手機單欄與底部導覽；手機持倉改成分行排列。正式 HTTPS 網站可加入主畫面，以 standalone 模式開啟。
- 2.2 的計算、報價、儲存、備份與 Firestore 規則，與交付的 2.0 逐位元組相同；此次調整呈現、安裝提示及 PWA 設定。
- 持倉搜尋、類別篩選、排序、成本輸入檢查與報價失敗提示。
- 可選擇共享持倉與接收者；朋友查看數量、市值、未實現損益與百分比。朋友沒有編輯你的持倉功能。
- 長線、短線策略分頁，記錄交易理由、進場條件、失效／退出條件、持有時間與狀態。新策略預設私人草稿。
- 新增策略直接沿用上方已選的長線／短線分類。策略作者可對策略授權名單發起投票，截止後按同意／不同意票數結算；投票者可顯示自己的 Google 名稱與頭像。
- App 管理員可核准或退回其他使用者已分享給管理員查看的策略。管理員核准不會自動下單，也不會修改策略執行狀態。
- 持倉與策略各自有授權名單。邀請接受後，擁有者仍需勾選授權並儲存。
- 每筆持倉、每日紀錄分開保存。持倉編輯衝突會提示重新編輯；行情更新不覆蓋數量與成本。
- 保留成功行情的時間；報價失敗不假裝更新成功。匯率變動時重新一致換算市值與成本。
- 美元帳戶總值可設為參考值，避免與個股重複加總。
- 紀錄日期固定使用 Asia/Taipei；達標試算處理零資產、已達標、到期與高報酬需求。
- JSON 備份包含持倉、策略、目標與歷史，排除 API 金鑰與分享授權；另可匯出持倉 CSV。

## 本機開發與檢查

需要現代版本的 Node.js（建議 22 以上）。核心測試無外部套件：

```bash
npm test
python3 -m http.server 8000
```

以瀏覽器開啟 `http://localhost:8000/?demo=1` 可測試示範模式。開啟 `http://localhost:8000/` 登入前，需在 Firebase Authentication 設定允許該主機；這個操作沒有替你執行。

`npm test` 會重新建立獨立預覽，並執行計算、報價模擬、備份、儲存交易模擬與畫面產生邏輯測試。測試結果見 `VALIDATION.md`。

選用瀏覽器測試腳本為 `tests/ui.test.mjs`，需要另外安裝 Playwright 與 Chromium 並啟動本機網站。此環境沒有成功執行這份瀏覽器測試，不應把本機邏輯測試視為視覺或線上權限驗證。

## 資料與權限

| 路徑 | 用途 | 可讀取者 |
| --- | --- | --- |
| `users/{uid}` | 私人目標、私人報價金鑰、版本資訊 | 本人 |
| `users/{uid}/assets/{id}` | 每筆持倉與行情 | 本人 |
| `users/{uid}/history/{date}` | 每日資產紀錄 | 本人 |
| `users/{uid}/backups/v1` | 首次轉換前的原始資料 | 本人；建立後不可由 App 修改或刪除 |
| `sharedPortfolios/{uid}` | 被選取持倉的分享副本與名單 | 本人、持倉授權名單 |
| `strategyAccess/{uid}` | 策略授權名單 | 本人、策略授權名單 |
| `strategies/{uid}/posts/{id}` | 策略、私人草稿、分享狀態 | 本人；授權者僅能讀已發布策略 |
| `shareInvites/{id}` | 邀請與接受狀態 | 邀請者、該 Google 帳號接收者 |
| `strategyReviews/{uid}/posts/{id}` | 投票名單、結果及管理員核准狀態 | 策略作者、策略授權名單 |
| `access/{uid}` | App 使用資格 | 本人、管理員；只有管理員可核准 |

以上為隨附規則的預期行為，需先部署並以不同 Google 帳號驗證。App 使用資格與持倉／策略授權是兩件事。管理員資格不提供其他使用者私人持倉的讀取權。

## 估值口徑

目前提供估值與未實現損益，不包含交易紀錄、已實現損益、手續費、股利、配息或自動跟單。未填成本的部位不計入損益本金分母。

美元部位有買入匯率時使用固定台幣本金；未填買入匯率時，只按目前匯率換算美元價差，不代表完整匯兌損益。台股為收盤行情。報價來源的可用性、延遲、CORS 與速率限制需在正式網域檢查。

朋友可使用自己的 Finnhub 金鑰更新畫面估值；這不會改動持倉擁有者的數量、成本或私人設定。

目前最多共享 100 筆持倉；持倉與策略每份名單最多 20 位查看者。共享會透露所選部位的數量、成本與損益。撤銷會阻止後續讀取，無法收回對方已看過、下載或截圖的內容。

2.4.11 的前端發布與 Firestore 規則發布是兩項獨立操作。完整部署及規則驗證方式見 `UPGRADE.md`；本機測試不等於真實跨帳號驗證。

## 2.2 字體與配置調整

正文採 16px，說明多為 13–14px；中文字體優先使用裝置內建 PingFang TC／Microsoft JhengHei。標題、金額與輔助說明有固定層次，數字採等寬排列。電腦首頁將總資產與目標並排，趨勢橫跨下方；手機依序顯示總資產、目標、趨勢。持倉加大市值與間距，策略文字增加行距。原版配色、財務計算及雲端資料流程沿用。

## 2.3 排版與最近 10 筆紀錄

統一五頁標題：標題與操作按鈕同排，摘要獨立一行。手機報價按鈕縮為保留輔助文字的圖示按鈕；成本與數量欄位改為單欄，較寬視窗的兩欄輸入框依底線對齊。每日紀錄依日期排序只顯示最新 10 筆，不提供載入更多；較前筆的比較仍使用完整歷史，完整資料保留於儲存與備份；資產曲線維持顯示最近 30 筆。資料結構、計算與共享權限沿用。

本機測試與原始碼檢查不等於瀏覽器實機排版驗收；尚未部署或使用真實帳號驗證。

## 2.4 卡片操作與舊紀錄收合

總覽的新增持倉移到總資產卡片；持倉頁的新增與刷新移到列表工具列；記錄今天移到資產曲線卡片，採一致 44px 按鈕。每日紀錄預設顯示最新 10 筆，較早紀錄在原生 details 區塊預設收起，可展開或收起；較早紀錄每頁最多 10 筆。翻頁維持展開，資料不會刪除。

## 2.4.1 總覽操作

移除總覽的新增持倉，持倉管理集中在「我的持倉」頁。Google 登入後自動載入原 Firebase 帳號資料，首次轉換前會建立備份；自動每日紀錄只在登入成功載入後執行，有持倉才會寫入，已有當日紀錄不覆蓋。無背景每日排程。


## 2.4.2 持倉與操作介面

持倉頁刷新按鈕明確顯示「更新報價」，完成後可再次刷新；更新中會防止重複請求。修正手機編輯持倉的關閉按鈕尺寸、內容焦點外框與深色勾選框；Google 大頭照恢復顯示，持倉使用代號專屬色識別；美元市值與上次成功的行情估值加上清楚標籤。未更動財務計算或雲端資料格式。


## 2.4.3 視窗關閉鍵

持倉與策略視窗統一使用線條式關閉圖示，保留 44px 觸控範圍；視窗開啟時，關閉鍵不再出現突兀的黃色外框，鍵盤焦點保留低調可辨識的邊框。


## 2.4.4 手機設定與帳號管理

- 限制 iPhone 日期輸入欄位寬度，避免超出財務目標卡片。
- 使用者管理改在帳號卡片內展開，立即顯示載入狀態；讀取失敗時提供重試。
- 沒有更動持倉、報價、每日紀錄、分享授權或雲端資料結構。


## 2.4.5 管理名單收合

- 使用者管理按鈕可展開與收合，載入中仍可收合。
- 快速重開會共用進行中的名單讀取；已載入後重開不重複查詢。


## 2.4.6 總資產卡片

- 台幣總額為主要視覺，持倉數為輔助資訊；目標金額仍在目標卡片中。
- 浮動損益分區顯示，成本覆蓋與匯差說明可展開查看。
- 更新時間與更新報價整齊排列在底部。
- `device-preview.html` 是本版的互動示範，可切換手機及電腦版；不讀取真實帳號資料。
